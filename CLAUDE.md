# Notes for Claude

- **Start every session by reading `docs/tracker.html`.** The JSON in `<script id="tracker-data">` is the source of truth for status, next steps, open questions and decisions. Go through "To discuss" with the user before building anything new.
- **Keep the tracker current as you work** (the user asked for this), not only at the end of a session. Update the JSON as tasks start and finish: bump `updated`, add a `sessions` entry, move finished `next` items into `milestones`, and record new `decisions` and `discuss` questions. Keep it valid JSON and leave the page markup and script alone.
- **This is a team repo** (private, `AR13X3/team-sheeeep`). Follow `CONTRIBUTING.md`: each member works on their own branch named after them (`joy` for the owner, then `sami`, `apurva`, `nila`, `nyla`, `dewmini`; an extra branch uses a dash, `sami-topic`, never `sami/topic`), nobody commits to `main` directly, and a finished task becomes a pull request into `main` (template in `.github/`, merged with a merge commit, not squash). Merge `origin/main` into the branch before starting new work. Commit or push only when the person you're working with asks.
- The repo owner is a visual person and prefers HTML pages to markdown. `docs/readme.html` and `docs/plan.html` are the visual docs. The plain-text docs are `README.md` (landing page: setup, team, structure, commands), `docs/how-it-works.md` (pages, data sources, accuracy, planner, design) and `CONTRIBUTING.md` (workflow and design rules). Update the visual and plain-text versions together when features change.
- Never commit keys or tokens. Local keys go in `.env.local` (ignored by Git).
- Button fill and text colours must stay exactly as in the Figma design. The rest of the UI is no longer locked to the Figma frames (session 4 redo): keep the palette, Lato and Manami, and build with the semantic tokens in `src/styles/tokens.css` (`--bg`, `--surface`, `--text`, `--border`…) so light and dark themes both work. Never hard-code a light-only colour.
- Layout: signed-in pages render inside `src/components/shell/AppShell.jsx` (sidebar, top bar, Ctrl K, Manami panel) and use `<Page>` from `src/components/Page.jsx` for the header, setup stepper and Manami tip. The app fills the window at real size (no page zoom); only `.shell__content` scrolls. Farm-level numbers (plan, soil health, crop mix, alerts) come from `useFarm()` in `src/state/useFarm.js`. Check fit with `npm run test:e2e -- fit` (default window 1280×665).
- Refresh the doc screenshots in `docs/img` with `node tools/e2e/_doc-shots.mjs` (dev server running) after visible changes.
- Dev server: `preview_start` with name `web` (`.claude/launch.json`) → http://localhost:5173. Docs are also served there at `/docs/tracker.html`.
- Checks: `npm run build`, `npm run check:docs` (tracker JSON + doc links), `npm run test:e2e` (dev server running), `npm run validate:phenology`. CI (`.github/workflows/ci.yml`) runs build + check:docs on every pull request; Cloudflare builds a preview of each branch at `https://<branch>-team-sheeeep.joytoufiqahmed.workers.dev`.
- The Word project breakdown (`docs/TEAM-SHEEEEP-Project-Breakdown.docx`) is generated by `python tools/docs/build_breakdown.py`. Update its text and re-run it when features or numbers change.
